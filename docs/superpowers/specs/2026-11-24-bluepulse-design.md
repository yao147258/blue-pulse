# BluePulse 设计文档

- **日期**：2026-11-24
- **状态**：已经用户确认
- **项目**：基于 ESP32-S3 的电脑指标蓝牙监控仪表盘

## 1. 项目概述

BluePulse 是一套由两个程序组成的系统：Windows 电脑上的指标采集程序通过 BLE（低功耗蓝牙）把 CPU、内存、GPU、网络、磁盘等指标推送到桌面的 ESP32-S3 触摸屏设备上，设备以多页仪表盘的形式实时展示。

**核心决策（已确认）：**

| 决策点 | 结论 |
|---|---|
| 设备形态 | 带触摸的多页仪表盘，纯展示、不下发命令 |
| 硬件 | 微雪 ESP32-S3-Touch-LCD-1.54（1.54" 240×240，ST7789 + CST816） |
| 通信方式 | BLE GATT，单 Notify 特征值，单向数据流 |
| 电脑端 | C# + .NET Framework 4.8，托盘程序，单 exe 免安装 |
| 设备端 | ESP-IDF（C），LVGL 9 UI |
| 监控指标 | CPU（占用/温度/频率/每核）、内存、GPU（占用/显存/温度）、网络、磁盘 |

**明确不做（第一版）：**

- 不从设备向电脑下发任何控制命令（睡眠、关机等）。
- 不做 Wi-Fi 通道（协议层预留扩展，传输层只做 BLE）。
- 不做配置界面/配网页面，所有参数编译期或配置文件写死。
- 不做多电脑切换、多设备连接。

## 2. 总体架构

```
┌─────────────────────┐   BLE GATT (Notify)   ┌──────────────────────┐
│  Windows 采集端      │ ────────────────────▶ │  ESP32-S3 固件        │
│  BluePulseHost.exe  │    JSON 数据包         │  1.54" 触摸屏仪表盘   │
│  (C# .NET Fx 4.8)   │ ◀──────────────────── │  (ESP-IDF, C)        │
└─────────────────────┘  (无下行命令，仅连接管理) └──────────────────────┘
```

- **数据流**：单向。电脑 → 设备每秒推送一帧指标 JSON；设备 → 电脑只有 BLE 协议栈自身的连接事件，无应用层下行数据。
- **触摸交互**：仅操作设备本地 UI（切页），不产生网络流量。

## 3. 硬件

| 项 | 选择 | 说明 |
|---|---|---|
| 主控 | 微雪 ESP32-S3-Touch-LCD-1.54 | ESP32-S3R2，240×240 彩屏 + 电容触摸，约 ¥70~90 |
| 屏幕 | ST7789 驱动，SPI 接口 | 微雪提供例程，LVGL 支持成熟 |
| 触摸 | CST816S，I2C 接口 | 中断引脚 + I2C 读取坐标 |

| 电脑侧蓝牙 | 电脑自带蓝牙或 USB 适配器，蓝牙 4.0+ | Windows 10 19045 原生 BLE 栈 |

## 4. 通信协议（BLE GATT）

### 4.1 GATT 布局

- **设备名**：`BluePulse`（广播名与 GATT Generic Access 一致）。
- **服务 UUID**：自定义 128-bit，`6E40FE10-B5A3-F393-E0A9-E50E24DCCA9E`（沿用 Nordic UART 风格的基座，避免与标准服务冲突）。
- **特征值**：
  - `6E40FE11-...`（Notify）：电脑端订阅后接收数据帧。
  - `6E40FE12-...`（Write，保留）：第一版不使用，仅预留协议扩展位。
- **MTU**：连接建立后协商至 247 字节；每包有效载荷 ≤ 244 字节（3 字节 ATT 头开销）。

### 4.2 分包格式

超过 MTU 的帧拆为多个 BLE 包，包头 2 字节：

```
字节 0：高 4 位 = 帧类型（0x01 = 指标帧），低 4 位 = 包序号（0 起）
字节 1：总包数（1~15）
字节 2..：JSON 分片（UTF-8）
```

- 单包能装下的帧同样走该格式（总包数 = 1），协议统一。
- 设备端收齐所有分片后拼装解析；任一帧超时（3 秒）未收齐则丢弃整帧，等待下一帧。

### 4.3 数据帧（JSON，每 1 秒一帧）

```json
{"t":123456,"cpu":{"load":37,"temp":52,"freq":3600,"percore":[35,40,38,36]},
 "mem":{"pct":61,"used":9.8,"total":16.0},
 "gpu":{"load":12,"temp":48,"vram":2.1},
 "net":{"up":120,"down":850,"today":3.2},
 "disk":{"c":{"pct":70},"d":{"pct":45}}}
```

字段约定：

- `t`：电脑端 Unix 时间戳（秒），供设备显示时钟用（可选）。
- `cpu.load`/`mem.pct`/`gpu.load` 等：百分比 0~100 整数。
- `temp`：摄氏度整数；传感器读不到时该字段省略（设备端显示 `--`）。
- `freq`：MHz 整数，取当前平均频率。
- `percore`：每核占用率数组，长度随电脑核数，设备端最多渲染前 8 核。
- `used`/`total`：GB，一位小数。
- `net.up`/`net.down`：当前速率，单位 Kbps，整数。
- `net.today`：当日累计流量，GB，一位小数。
- `disk`：键为盘符小写字母，`pct` 为占用百分比。
- 采样瞬间某指标不可用时字段省略，**不发送 null**。

### 4.4 连接管理

- **设备端**：上电即广播；连接建立后停止广播；断连后 1 秒内重新广播。
- **电脑端**：启动后按设备名扫描，发现即连接；断连后指数退避重连（1s → 2s → 4s → …上限 30s），收到任何数据帧即重置退避。
- **帧率**：1 秒/帧。BLE 吞吐下够用且稳定；屏幕 UI 由设备端本地 30fps 渲染，数据变化用插值平滑过渡。

## 5. 电脑端（BluePulseHost，C# .NET Framework 4.8）

### 5.1 模块划分

| 模块 | 职责 | 关键依赖 |
|---|---|---|
| `MetricsCollector` | 每秒采集一轮指标，输出指标对象 | `PerformanceCounter`（CPU/内存/磁盘/网络）、LibreHardwareMonitor（温度/频率/GPU）、NVML（N 卡，可选） |
| `JsonFrameBuilder` | 指标对象 → 协议 JSON → 分包字节数组 | 内置序列化（手写或轻量库，避免大依赖） |
| `BleSender` | 扫描、连接、订阅 Notify、发包、重连 | Windows.Devices.Bluetooth（WinRT API，经 CsWinRT 引用） |
| `TrayUI` | 托盘图标（连接状态着色）、右键菜单：立即重连/退出 | `NotifyIcon` |
| `AppLifetime` | 单实例互斥、启动参数、错误日志 | — |

### 5.2 行为细节

- 单实例运行（命名互斥量），二次启动唤起已有实例。
- 日志写 `%LOCALAPPDATA%\BluePulse\host.log`，滚动保留 1 MB。
- 托盘图标：绿色=已连接、灰色=扫描中、红色=适配器不可用。
- 开机自启：不内置设置界面，文档说明手动放快捷方式到启动文件夹。
- 温度读取依赖 LibreHardwareMonitor 的内核驱动，程序首次以管理员权限运行一次完成安装；托盘菜单提供"以管理员重启"。

### 5.3 产出

- 单个 exe（约 200~300 KB），目标机器零依赖（Win10 19045 自带 .NET Framework 4.8）。
- 测试工程 `BluePulse.Tests`（MSTest 或 NUnit），覆盖 JSON 帧构建、分包逻辑、指标格式化。

## 6. 设备端（BluePulse 固件，ESP-IDF + C）

### 6.1 技术栈

- ESP-IDF（最新稳定版，v5.x），NimBLE 主机栈。
- LVGL 9 作为 UI 框架，ST7789 + CST816 用现成组件（`esp_lcd` + 微雪例程移植）。

### 6.2 页面设计（240×240，共 3 页）

| 页 | 内容 |
|---|---|
| 页 1 总览 | CPU/内存/GPU 三个圆环 + CPU 温度数字 |
| 页 2 性能 | CPU 占用 60 秒历史曲线 + 每核占用条形图（最多 8 核） |
| 页 3 网络/磁盘 | 上/下行速率、当日累计流量、各磁盘占用条 |

- **交互**：左右滑动切页（LVGL 手势），底部页面指示点。
- **渲染**：数据 1Hz 更新，数值/圆环用 LVGL 动画平滑过渡到新值。
- **断连状态**：屏幕顶部状态条显示"未连接"；断连超 10 秒进入低亮度模式（背光 PWM 降到 30%），收到数据恢复。

### 6.3 任务划分

| 任务 | 优先级 | 职责 |
|---|---|---|
| `ble_host_task` | 高 | NimBLE 事件循环，收包、拼帧，投递到队列 |
| `ui_task` | 中 | LVGL 定时器 + 渲染，从队列取数据更新控件 |
| `lvgl_tick` | 由 `esp_timer` 驱动 | LVGL 时基 |

- 队列深度 2，满了丢旧帧（UI 只关心最新数据）。
- 堆预算：LVGL 绘制缓冲用 SPIRAM（板载 2MB PSRAM），内部堆留给 BLE 栈。

### 6.4 固件工程结构


| 层 | 方法 |

## 9. 开发顺序

1. **电脑端采集 + BLE 发送**：先在 PC 上跑通指标采集，用 nRF Connect 验证广播与数据帧。
2. **设备端显示骨架**：屏幕点亮 + LVGL 三页 UI，用硬编码假数据渲染。
3. **设备端 BLE 接入**：GATT 服务 + 收包解析，与电脑端联调。
4. **触摸与打磨**：滑动切页、断连处理、动画、背光。
5. **稳定性**：长时间运行测试、日志、重连鲁棒性。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| Windows BLE API（WinRT）在 .NET Framework 4.8 下引用繁琐 | 用 CsWinRT 生成互操作程序集；若受阻，退化方案是 `BluetoothLEAdvertisementWatcher` + Win32 降级路径，仍不出第三方大依赖 |
| LibreHardwareMonitor 驱动需要管理员权限 | 首次运行引导 + manifest 声明 `requireAdministrator` 可选；温度拿不到时字段省略，UI 显示 `--`，不阻塞其他指标 |
| BLE 吞吐不足或丢帧 | 协议有分片与帧超时机制；必要时把帧率降到 2 秒/帧（配置项） |
| LVGL + NimBLE 内存吃紧 | LVGL 缓冲放 PSRAM；帧 JSON 解析用流式/固定缓冲，解析完立即释放 |
| 微雪板子引脚定义与例程版本差异 | BSP 组件集中管引脚，以微雪 wiki 的原理图为准，不散落在业务代码里 |
